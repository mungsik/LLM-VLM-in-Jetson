# 설계: 멀티턴 한국어 챗봇 데이터 재구성 + 재학습 (Approach B, 2026-06-29)

## 배경 / 왜 이걸 하나

kd-v1(full-FT logit-KD) 평가 결과: 지식(KMMLU 41%)은 보존됐으나 채팅 품질은 옛 scaleup과 동급(wash). 학습 데이터(`scaleup_teacher.jsonl`)를 직접 분석해 원인을 데이터에서 확인:

- **100% 단일턴**(메시지 2개) — 여러 턴 이어가기를 한 번도 안 배움
- **영어섞임 41.6%** — teacher(Phi-4) 답변 자체가 영어를 섞음
- **"모른다" 0.5%** — 모를 때 모른다고 하는 예시가 사실상 없음 → 환각
- **출처 2개뿐**(KoCommercial 15k + kullm-v2 9.9k), 수학·기술 치우침. 의도했던 지시·형식 합성 데이터 5k 등은 통째 누락

용도는 **계속 주고받는 한국어 대화 챗봇**(사용자 확정). 학습 강도 레버는 소진됐고, 병목은 데이터 → 데이터를 다시 만든다.

## 목표

depth-pruned student를 멀티턴 한국어 챗봇으로 재학습하되, 위 4가지 약점을 데이터 단에서 해소.
- 성공: 멀티턴 프로브에서 맥락 유지 + 단일턴 프로브에서 영어섞임↓·환각↓·지시준수↑, KMMLU 큰 회귀 없음.

## 데이터 (전부 실측 검증 완료)

### A. 메인 멀티턴 뼈대 — `lemon-mint/smol-koreantalk`
- 실측(400 대화 샘플): 멀티턴 75%, 평균 4.6메시지, OpenAI `messages`/`role` 형식.
- **문제: assistant 답변의 44.6%가 영어 ≥5% 섞임.** 생짜로 쓰면 영어섞임을 강화 → 금지.
- **영어 필터(토큰종류 구분):** 단순 라틴비율이 아니라 **영어 산문 vs 허용 토큰(코드/JSON 키/약어/URL/제품·모델명)**을 구분. 문장단위 언어판별로 "영어 문장"이 섞인 턴만 제외(코드블록·인라인 기술용어는 허용). 단순 5% 컷은 'Python' 한 번 쓴 좋은 한국어 대화도 버리므로 부적절(codex 지적).
- **번역투 측정(필수, "허용 가능"은 근거 없는 가정):** 영어 제거 ≠ 자연스러운 한국어. 살아남은 표본 수백 개에 **LLM 심사 자연스러움 점수**(번역투/어색함)를 매겨 **저점수 대화 제외 또는 가중치 하향**. 측정 없이 채택 금지.
- **코퍼스 가중(핵심):** smol(번역, ~15만) ≫ korquad-chat(원어민, 9.6천)이라 그냥 합치면 **번역투가 최종 모델을 지배**. → korquad-chat **업샘플링** + 번역 데이터 **비중 상한** 설정 + 가능하면 원어민 멀티턴(예: smol-koreantalk 외 추가 원어민 소스 탐색)으로 보강. 최종 코퍼스의 번역:원어민 비율을 명시 관리.

### B. 원어민·지문근거 보강 — `heegyu/korquad-chat-v1`
- 9,619건. KorQuAD 위키 지문 기반 ChatGPT 생성 멀티턴(3~4턴).
- 실측: **자연스러운 원어민 한국어, 봇 답변 영어 없음, 지문 근거.** 영어섞임·번역투 문제 없음.
- 형식: `text` 필드에 `<sys>`(지문)+`<usr>`/`<bot>` 토큰 → **파서로 messages 변환 필요**.
- 한계: ChatGPT 생성이라 가끔 지문과 미세하게 어긋남(샘플서 1건). 작고(9.6k) 지문-QA 스타일로 좁음.

### C. "모른다" 보강 — 합성(기성 한국어 데이터 부재)
- **답 없는 질문 → 모른다:** 가상/미래/검증불가 질문(없는 지명, 미래 수상자 등) → "확실하지 않습니다/모르겠습니다".
- **지문 근거 모른다:** KorQuAD 지문 + 지문에 답 없는 질문 → "지문에 없어 알 수 없습니다"(SQuAD 2.0 unanswerable 방식).
- **짝지은 answerable 음성예시(필수, codex 지적):** 같은 도메인에서 한쪽은 근거로 답 가능, 한쪽은 불가 → 둘을 쌍으로. 모호하면 거부 대신 **되묻기(clarifying question)** 예시도 포함. 거부/응답 **캘리브레이션**이 목적.
- 규모: 수천 건. **비율 ≤ 5~10%** (과하면 답 가능한 것도 거부하는 겁쟁이 모델 됨).

### D. 지시·형식 보강 — 합성 + 프로그램 검증
- 제약 프롬프트 생성(정확히 N개 목록 / JSON만(키 지정) / 표 / 금지어 / 마지막문장 고정 등).
- 답을 생성하되 **제약 충족을 기계로 검증**(목록 개수·JSON 파싱·금지어 검사)해 통과분만 채택. 단 이는 **형식 준수만 보장**하지 답 내용 품질은 보장 못 함(codex 지적) → 내용은 별도 표본 점검.
- **다양성 목표 명시(codex 지적):** 기존 생성기는 6주제×6형식뿐. 주제·제약 유형을 대폭 확장하고 **held-out 제약 유형**(학습에 없던 형식)을 평가용으로 분리.
- 출발점: 누락됐던 `prepare_distill_prompts.py`의 synthetic-ko-ifeval 생성기 복원·확장. 설계 참고로 로컬 `allganize/IFEval-Ko`(평가셋) 유형 참조.
- 규모: 수천 건.

### 제외
- `junelee/sharegpt_deepl_ko`(DeepL 번역, 번역투+영어섞임+스키마 불일치), `maywell/koVast`(번역투). 둘 다 실측 기준 미달.

## 학습

- **방법: 평범한 멀티턴 SFT (logit-KD 폐기).** KD는 Phi-4 분포를 따라가게 해 영어섞임을 재유입 → 부적합. 사람/원어민 답을 직접 학습하는 plain CE가 맞음.
- **멀티턴 라벨 마스킹(엣지케이스 명시, codex 지적):** `src/distill/chat_labels.py`를 확장 — **여러 assistant 턴 각각** supervise, user/system 턴 마스킹(-100). 처리할 함정: 다중 assistant 스팬, system(`<sys>`) 토큰, chat-template 경계 토큰, **턴 중간에서 잘린 truncation**(부분 턴 라벨 제외), assistant **EOS 토큰 학습 여부**, **user 턴으로 끝나는 대화**. 단위테스트는 정확한 토큰 스팬을 단언(단순 user=-100/assistant=학습 수준 넘어).
- 베이스: `artifacts/phi4-pruned-depth-masked`. full-FT, paged_adamw_8bit, save_only_model. KD 손실 대신 표준 CE(assistant 토큰만).
- **학습 예산 명시(KD에서 복붙 금지, codex 지적):** epoch는 token 수 기준으로 결정 — max_length, packing 여부, **validation loss + early stop**, 그리고 **소규모 파일럿(수천 대화) 먼저** 돌려 epoch/lr 확정 후 본런. epoch 2~3·lr 1e-5는 시작값일 뿐 파일럿으로 검증.
- **망각 완화(codex 지적):** 번역 챗 데이터로 full-FT 시 한국어 지식·추론 퇴화 위험. → 학습 코퍼스에 **지식·추론 데이터 일부 유지**(현 KoCommercial/kullm의 수학·기술 일부) + 평가를 KMMLU 외 추론까지 확장 + lr/epoch 절제. (필요 시 LoRA 옵션도 후보.)
- 데이터 통합 포맷: 전부 `messages`(role/content)로 정규화 → 단일 학습 파일.

## 검증 (codex: 기존안은 회귀탐지용일 뿐 품질증명 불가 → 강화)

- **LLM 심사 페어와이즈(핵심 추가):** 신모델 vs kd-v1 vs scaleup를 **쌍대 비교**(자연스러움·도움됨·일관성). 회귀가 아니라 "정말 좋아졌나"를 증명.
- **멀티턴 평가는 "고정 벤치"가 아니라 "방법"으로:** 한국어 멀티턴 표준 벤치는 빈약하다(LogicKor는 2024-10 archived, Ko-MT-Bench도 구형, 2025~26 후속 부재 — 한국어 평가는 지식·추론 단일턴에 몰림). 따라서:
  - **1순위: LLM-심판 페어와이즈** — kd-v1/scaleup vs 신모델을 **그 시점 현행 강모델**(특정 모델 고정 금지)로 쌍대 비교. 방법 기반이라 안 늙음.
  - **프롬프트셋: 자체 held-out 멀티턴 프로브**(5~8메시지·주제전환·정정·되묻기·두 턴 전 참조) — 우리 챗봇 용도에 맞춤.
  - **LogicKor 42문항은 참고용 고정 잣대로만**(archived여도 상대비교엔 동작) 선택 사용. 의존 안 함.
- **자연스러움/번역투 점수:** 출력 표본에 LLM 심사 자연스러움 스코어(데이터 단계 측정과 동일 기준).
- **answerable vs unanswerable 캘리브레이션:** 답 가능 질문엔 답하고, 불가엔 모른다 하는 비율을 둘 다 측정(겁쟁이화 탐지).
- **자동 지표:** 출력 영어섞임 비율(영어 산문 vs 허용 토큰 구분해 측정), 지시·형식 준수율(held-out 제약 포함).
- **단일턴 프로브 15개(기존)** + **KMMLU 가드(명시 임계):** 부분셋→full, **41% 대비 -2pt 이상 하락 시 실패**로 간주(롤백/조정). 추론 평가도 1종 추가.
- 디코딩 기본값: rep_penalty 1.15 + temp 0.7(kd-v1에서 반복 해결 확인).

## 컴포넌트 (구현 단위)

1. `scripts/build_chat_corpus.py` — 4종 로드·정규화(messages)·**토큰종류 구분 영어필터**·코퍼스 가중(번역:원어민 비율 관리)·모른다 비율·병합 → 단일 학습 jsonl.
2. `scripts/score_naturalness.py` — 살아남은 표본에 LLM 심사 자연스러움/번역투 점수 → 저점수 제외/가중.
3. `src/distill/chat_labels.py` 확장 — 멀티턴 마스킹(위 엣지케이스) + **정확한 토큰 스팬 단위테스트**.
4. `scripts/synth_instructions.py` — 지시·형식 합성 + 프로그램 검증(다양성·held-out 유형).
5. `scripts/synth_idk.py` — "모른다" 합성(가상질문 + 지문 unanswerable + answerable 짝 + 되묻기).
6. `scripts/train_sft_multiturn.py` — full-FT 멀티턴 SFT(표준 CE, val loss/early stop, 파일럿 우선).
7. 평가: 멀티턴 held-out 벤치 + **LLM 페어와이즈(vs kd-v1/scaleup)** + 자연스러움/영어섞임/모른다 캘리브레이션/지시 자동지표 + KMMLU(명시 임계) + 추론 1종.

## 범위 밖 (YAGNI)

- 새 teacher 생성 파이프라인(이번엔 기성 데이터 정제), RAG, **초장문(수십 턴) 장문맥 특화**, 양자화.
- 단 **5~8 메시지 + 정정·주제전환·되묻기 대화는 범위 안**(codex 지적 — "계속 주고받는" 챗봇 목표상 학습·평가에 포함). 제외하는 건 그 이상의 장문맥 특화뿐.
